# «Вита» — User Story Map, прототипы и модель потоков данных

Учебный проект в рамках курса «Системный анализ» (Яндекс Практикум, 2026). Модуль: проектирование продукта — от карты пользовательских историй до модели данных.

## Контекст

«Вита» — мобильное приложение для медицинской клиники. Автоматизирует взаимодействие пациента с клиникой: запись на приём, получение назначений, прохождение обследований в лаборатории, отслеживание результатов анализов, курс лечения. Задача проекта — от описания идеи довести продукт до прототипов ключевых экранов и модели потоков данных для MVP.

## Что сделано

| Этап | Артефакт | Результат |
|------|----------|-----------|
| **1. Описание проекта** | Продуктовая идея, целевая аудитория, бизнес-задача | Формализованная концепция |
| **2. User Story Map + MVP** | Карта пользовательских историй в Miro | Скоуп MVP выделен из общей карты |
| **3. Прототипы** | UI-макеты ключевых экранов в Figma | Прототип клиентского пути |
| **4. DFD** | Контекстная диаграмма и декомпозиция первого уровня | Модель потоков данных между акторами |

## Ключевые сущности предметной области

| Актор / Хранилище | Роль в системе |
|-------------------|----------------|
| Пациент | Инициирует записи, проходит обследования и лечение, получает результаты |
| Врач | Назначает обследования и лечение, работает с карточками пациентов |
| Лаборатория | Проводит анализы, передаёт результаты в приложение |
| Приложение «Вита» | Оркеструет процессы, хранит расписание, назначения, результаты |

## Методология и инструменты

- **User Story Mapping** — Jeff Patton
- **MVP scoping** — выделение минимально ценного релиза из полной карты
- **DFD (Data Flow Diagram)** — контекстная модель + декомпозиция первого уровня
- **Инструменты:** Miro, Figma, draw.io

## Чему научился

- Строить User Story Map от целей пользователя вниз к пользовательским задачам
- Отрезать MVP от полного скоупа по бизнес-ценности и стоимости
- Проектировать UI-прототипы под конкретные пользовательские истории
- Формализовать потоки данных между внешними акторами, процессами и хранилищами
- Работать в связке аналитик — дизайнер (Figma) — команда (Miro)
